# Flujo de la entidad "perritos"

Proyecto **GH AUTOS**: backend en Node.js + Express + TypeScript (carpeta `BACKEND`) y frontend en Angular (carpeta `GH_AUTOS`).

Este documento explica el camino completo que recorren los datos de los perritos: salen de la base de datos PostgreSQL y terminan impresos en la consola del navegador.

---

## 1. Base de datos: tabla `perritos` (PostgreSQL)

**Dónde:** base de datos `venta_carros` en PostgreSQL (localhost, puerto 5432). La tabla se creó desde pgAdmin.

| Columna       | Tipo          | Significado                                      |
|---------------|---------------|--------------------------------------------------|
| `id_perritos` | `INTEGER`     | Identificador. Llave primaria que se genera sola (identity). |
| `nombre`      | `VARCHAR(50)` | Nombre del perrito                               |
| `edad`        | `INTEGER`     | Edad en años                                     |
| `raza`        | `VARCHAR(50)` | Raza                                             |
| `color`       | `VARCHAR(30)` | Color                                            |

La definición equivalente en SQL es esta:

```sql
CREATE TABLE perritos (
  id_perritos INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  nombre      VARCHAR(50) NOT NULL,
  edad        INTEGER     NOT NULL,
  raza        VARCHAR(50) NOT NULL,
  color       VARCHAR(30) NOT NULL
);
```

La tabla tiene 5 registros: Max, Luna, Rocky, Canela y Toby.

**En pocas palabras:** aquí viven los datos de verdad. Si se reinicia el servidor, los datos siguen ahí.

## 2. Conexión: cómo el backend se conecta a PostgreSQL

### 2.1 Archivo `BACKEND/.env`

Aquí se guardan los datos de conexión. Van **fuera del código** para que la contraseña no quede escrita en los archivos `.ts`.

```env
PORT=3000
DB_HOST=localhost
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=********      # la contraseña real solo está en el .env
DB_NAME=venta_carros
```

### 2.2 Archivo `BACKEND/src/config/database.ts`

```ts
import dotenv from 'dotenv';
import { Pool, types } from 'pg';

dotenv.config({ quiet: true });   // lee el archivo .env y llena process.env

export const pool = new Pool({
  host: process.env.DB_HOST,
  port: Number(process.env.DB_PORT) || 5432,
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME
});
```

- **`dotenv`** lee el `.env` y pone sus valores en `process.env`.
- **`pg`** es la librería que permite que Node.js hable con PostgreSQL.
- **`Pool`** es un "grupo de conexiones": mantiene varias conexiones abiertas y las reutiliza. No hay que abrir y cerrar una conexión en cada consulta, y así es más rápido.
- El `pool` se **exporta** para que todos los modelos (clientes, catálogo, compras, perritos) usen la misma conexión.

Además, en `BACKEND/src/server.ts` el servidor revisa la conexión antes de arrancar:

```ts
await pool.query('SELECT 1');
console.log(`Conectado a PostgreSQL (...)`);
```

Si la conexión falla, muestra un error y no arranca.

## 3. Modelo: `BACKEND/src/models/perritos.models.ts`

El **modelo** es la única parte que habla con la base de datos. Aquí están las consultas SQL.

### 3.1 La interfaz (la "forma" de un perrito en el backend)

```ts
export interface Perrito {
  idPerrito: number;
  nombre: string;
  edad: number;
  raza: string;
  color: string;
}
```

### 3.2 Los campos y el alias

```ts
const CAMPOS = 'id_perritos AS "idPerrito", nombre, edad, raza, color';
```

**¿Por qué el alias `AS "idPerrito"`?**
- En la base de datos la columna se llama `id_perritos`. Es la convención de SQL (snake_case: minúsculas con guion bajo).
- En JavaScript/TypeScript se usa **camelCase** (`idPerrito`), y el frontend espera ese nombre.
- El alias **renombra la columna en el resultado** sin cambiar la tabla, así el JSON sale con `idPerrito`.
- Las comillas dobles hacen falta porque PostgreSQL pasa a minúsculas los nombres sin comillas. Sin ellas saldría `idperrito`.

### 3.3 Las consultas SQL

```ts
export class PerritoModel {
  // Traer todos
  static async obtenerTodos(): Promise<Perrito[]> {
    const { rows } = await pool.query<Perrito>(
      `SELECT ${CAMPOS} FROM perritos ORDER BY id_perritos`);
    return rows;
  }

  // Traer uno por id
  static async obtenerPorId(id: number): Promise<Perrito | null> {
    if (!esIdValido(id)) return null;
    const { rows } = await pool.query<Perrito>(
      `SELECT ${CAMPOS} FROM perritos WHERE id_perritos = $1`, [id]);
    return rows[0] ?? null;
  }

  // Crear
  static async crear(perrito) {
    const { nombre, edad, raza, color } = perrito;
    const { rows } = await pool.query<Perrito>(
      `INSERT INTO perritos (nombre, edad, raza, color)
       VALUES ($1, $2, $3, $4)
       RETURNING ${CAMPOS}`,
      [nombre, edad, raza, color]);
    return rows[0];
  }

  // Actualizar: solo los campos que lleguen
  static async actualizar(id, datos) {
    const { set, valores } = construirSet(datos, COLUMNAS_ACTUALIZABLES);
    // UPDATE perritos SET nombre = $1, ... WHERE id_perritos = $n RETURNING ...
  }

  // Eliminar
  static async eliminar(id: number): Promise<boolean> {
    const { rowCount } = await pool.query(
      'DELETE FROM perritos WHERE id_perritos = $1', [id]);
    return (rowCount ?? 0) > 0;
  }
}
```

| Método         | SQL      | Devuelve                                  |
|----------------|----------|-------------------------------------------|
| `obtenerTodos` | `SELECT` | Lista de perritos                         |
| `obtenerPorId` | `SELECT ... WHERE` | Un perrito, o `null` si no existe |
| `crear`        | `INSERT ... RETURNING` | El perrito creado, ya con su id |
| `actualizar`   | `UPDATE ... RETURNING` | El perrito actualizado, o `null` |
| `eliminar`     | `DELETE` | `true` si lo borró, `false` si no existía |

**Consultas parametrizadas (`$1`, `$2`, ...):** los valores no se pegan dentro del texto SQL. Se mandan aparte, en un arreglo (`[id]`). Así PostgreSQL los trata siempre como **datos** y nunca como código, y eso **evita la inyección SQL**.

**`async/await`:** consultar la base de datos tarda un poco. `await` espera la respuesta sin bloquear el servidor, que puede atender otras peticiones mientras tanto.

## 4. Controlador: `BACKEND/src/controller/perritos.controller.ts`

El **controlador** recibe la petición HTTP (`req`), llama al modelo y arma la respuesta HTTP (`res`) con su código de estado. No escribe SQL.

```ts
export const obtenerPerritos = async (_req: Request, res: Response) => {
  res.json(await PerritoModel.obtenerTodos());
};

export const obtenerPerritoPorId = async (req: Request, res: Response) => {
  const perrito = await PerritoModel.obtenerPorId(Number(req.params.id));
  if (!perrito) return res.status(404).json({ message: 'Perrito no encontrado' });
  res.json(perrito);
};

export const crearPerrito = async (req: Request, res: Response) => {
  res.status(201).json(await PerritoModel.crear(req.body));
};

export const actualizarPerrito = async (req: Request, res: Response) => {
  const perrito = await PerritoModel.actualizar(Number(req.params.id), req.body);
  if (!perrito) return res.status(404).json({ message: 'Perrito no encontrado' });
  res.json(perrito);
};

export const eliminarPerrito = async (req: Request, res: Response) => {
  const eliminado = await PerritoModel.eliminar(Number(req.params.id));
  if (!eliminado) return res.status(404).json({ message: 'Perrito no encontrado' });
  res.status(204).send();
};
```

| Función               | Qué hace                                                  | Respuesta |
|-----------------------|-----------------------------------------------------------|-----------|
| `obtenerPerritos`     | Pide todos al modelo y los devuelve en JSON               | 200 |
| `obtenerPerritoPorId` | Lee el `id` de la URL (`req.params.id`) y busca ese perrito | 200, o 404 si no existe |
| `crearPerrito`        | Toma los datos del cuerpo de la petición (`req.body`) y lo crea | 201 (Creado) |
| `actualizarPerrito`   | Toma el `id` de la URL y los datos nuevos del cuerpo      | 200, o 404 |
| `eliminarPerrito`     | Borra el perrito con ese `id`                             | 204 (sin contenido), o 404 |

Si ocurre un error inesperado (por ejemplo, la base de datos se cae), Express lo envía al middleware `src/middleware/eroror.middleware.ts`, que responde 500 ("Error interno del servidor").

## 5. Rutas: `BACKEND/src/routes/perritos.routes.ts` y registro en `app.ts`

### 5.1 Las rutas

Las **rutas** conectan cada método HTTP + URL con su función del controlador.

```ts
const router = Router();
router.get('/', obtenerPerritos);
router.get('/:id', obtenerPerritoPorId);
router.post('/', crearPerrito);
router.put('/:id', actualizarPerrito);
router.delete('/:id', eliminarPerrito);

export default router;
```

`:id` es un **parámetro**: en `/perritos/2`, el valor `2` llega al controlador como `req.params.id`.

### 5.2 Registro en `BACKEND/src/app.ts`

```ts
import perritosRoutes from './routes/perritos.routes';

app.use(cors());           // permite que Angular (otro puerto) llame a la API
app.use(express.json());   // convierte el cuerpo JSON de la petición en req.body
...
app.use('/api/v1/perritos', perritosRoutes);
```

`app.use` le pone el prefijo `/api/v1/perritos` a todas las rutas del router.

### 5.3 URL expuesta

Base: **`http://localhost:3000/api/v1/perritos`**

| Método   | URL                     | Acción                  |
|----------|-------------------------|-------------------------|
| `GET`    | `/api/v1/perritos`      | Listar todos            |
| `GET`    | `/api/v1/perritos/:id`  | Ver uno                 |
| `POST`   | `/api/v1/perritos`      | Crear                   |
| `PUT`    | `/api/v1/perritos/:id`  | Actualizar              |
| `DELETE` | `/api/v1/perritos/:id`  | Eliminar                |

**¿Por qué `cors()`?** Angular corre en un puerto (por ejemplo 4200) y el backend en otro (3000). Por seguridad, el navegador bloquea las peticiones entre orígenes distintos, salvo que el servidor las permita. `cors()` las permite.

## 6. Frontend – interfaz: `GH_AUTOS/src/app/Models/PerritosModels.ts`

```ts
export interface Perrito {
  idPerrito: number;
  nombre: string;
  edad: number;
  raza: string;
  color: string;
}
```

**¿Para qué sirve?** Le dice a TypeScript cómo es un perrito en el frontend. Tiene los mismos nombres que el JSON que manda el backend (por eso es `idPerrito`, gracias al alias del paso 3).

Sirve para:
- que el editor **autocomplete** (`perrito.raza`);
- que TypeScript **avise de errores** al compilar, por ejemplo si se escribe `perrito.razaa`.

Solo existe mientras se programa. No genera código en el navegador.

## 7. Frontend – servicio: `GH_AUTOS/src/app/services/perritos.service.ts`

```ts
@Injectable({ providedIn: 'root' })
export class PerritosService {
  private readonly url = 'http://localhost:3000/api/v1/perritos';

  constructor(private http: HttpClient) {}

  getPerritos(): Observable<Perrito[]> {
    return this.http.get<Perrito[]>(this.url);
  }

  getPerrito(id: number): Observable<Perrito> {
    return this.http.get<Perrito>(`${this.url}/${id}`);
  }

  crearPerrito(perrito: Omit<Perrito, 'idPerrito'>): Observable<Perrito> {
    return this.http.post<Perrito>(this.url, perrito);
  }

  actualizarPerrito(id: number, perrito: Partial<Perrito>): Observable<Perrito> {
    return this.http.put<Perrito>(`${this.url}/${id}`, perrito);
  }

  eliminarPerrito(id: number): Observable<void> {
    return this.http.delete<void>(`${this.url}/${id}`);
  }
}
```

- **`@Injectable({ providedIn: 'root' })`**: Angular crea **una sola instancia** del servicio para toda la app y la entrega a quien la pida (inyección de dependencias).
- **`HttpClient`**: la herramienta de Angular para hacer peticiones HTTP. Está habilitada en `app.config.ts` con `provideHttpClient()`.
- Cada método corresponde a una ruta del backend: `get` va con GET, `post` con POST, `put` con PUT y `delete` con DELETE.
- **`Observable`**: la respuesta llega "en el futuro". **La petición no se envía hasta que alguien hace `.subscribe()`.**
- `<Perrito[]>` indica que la respuesta es una lista de perritos, según la interfaz del paso 6.
- `Omit<Perrito, 'idPerrito'>` significa "un perrito sin id" (al crear, el id lo pone la base de datos). `Partial<Perrito>` significa "algunos campos" (al actualizar).

## 8. Frontend – componente: `GH_AUTOS/src/app/views/menu/menu.component.ts`

Se usa el componente del **menú** porque se carga siempre que se abre la app, en cualquier página.

```ts
import { PerritosService } from '../../services/perritos.service';

export class MenuComponent implements OnInit {

  private readonly perritosService = inject(PerritosService);

  ngOnInit(): void {
    this.perritosService.getPerritos().subscribe({
      next: (datos) => console.log('Perritos:', datos),
      error: (error) => console.error('No se pudieron cargar los perritos', error)
    });
  }
}
```

- **`inject(PerritosService)`**: pide a Angular la instancia del servicio.
- **`ngOnInit`**: método del ciclo de vida que Angular ejecuta **una vez, cuando el componente se crea**.
- **`.subscribe(...)`**: aquí se **envía de verdad** la petición HTTP.
  - `next`: se ejecuta cuando llega la respuesta. Imprime `Perritos:` y el arreglo en la consola.
  - `error`: se ejecuta si falla (por ejemplo, si el backend está apagado).

**Resultado en la consola del navegador (F12 → Console):**

```
Perritos: (5) [{…}, {…}, {…}, {…}, {…}]
  0: {idPerrito: 1, nombre: 'Max', edad: 3, raza: 'Labrador', color: 'Dorado'}
  1: {idPerrito: 2, nombre: 'Luna', edad: 2, raza: 'Pastor Alemán', color: 'Negro y café'}
  ...
```

> Nota: la app usa SSR (renderizado en el servidor), así que el mensaje también puede aparecer en la terminal donde corre `ng serve`.

## Diagrama del recorrido completo

```
 ┌──────────────────────┐
 │  PostgreSQL          │  tabla perritos (id_perritos, nombre, edad, raza, color)
 └──────────┬───────────┘
            │  SQL: SELECT id_perritos AS "idPerrito", ... FROM perritos
 ┌──────────▼───────────┐
 │  Pool (pg)           │  src/config/database.ts  ← datos de conexión del .env
 └──────────┬───────────┘
            │  pool.query(...)
 ┌──────────▼───────────┐
 │  Modelo              │  src/models/perritos.models.ts   → PerritoModel.obtenerTodos()
 └──────────┬───────────┘
            │  devuelve Perrito[]
 ┌──────────▼───────────┐
 │  Controlador         │  src/controller/perritos.controller.ts → res.json(perritos)
 └──────────┬───────────┘
            │
 ┌──────────▼───────────┐
 │  Ruta                │  src/routes/perritos.routes.ts + app.ts
 │                      │  GET /api/v1/perritos
 └──────────┬───────────┘
            │  HTTP (JSON)  http://localhost:3000/api/v1/perritos
 ┌──────────▼───────────┐
 │  Servicio Angular    │  services/perritos.service.ts → http.get<Perrito[]>()
 └──────────┬───────────┘
            │  Observable → subscribe()
 ┌──────────▼───────────┐
 │  Componente          │  views/menu/menu.component.ts → ngOnInit()
 └──────────┬───────────┘
            │  console.log('Perritos:', datos)
 ┌──────────▼───────────┐
 │  Consola navegador   │  F12 → Console
 └──────────────────────┘
```

En una línea:

```
PostgreSQL → Pool → Modelo → Controlador → Ruta → HTTP → Servicio Angular → Componente → Consola
```

La petición va de abajo hacia arriba (el componente pide los datos) y la respuesta vuelve de arriba hacia abajo (la base de datos entrega los datos).

## Cómo probarlo

1. Backend: `cd BACKEND` y luego `npm start`. Debe aparecer `Conectado a PostgreSQL` y `Servidor iniciado en http://localhost:3000`.
2. En el navegador, abrir `http://localhost:3000/api/v1/perritos`: salen los 5 perritos en JSON.
3. Frontend: `cd GH_AUTOS` y luego `ng serve`. Abrir la app, presionar F12 y ver `Perritos:` en la consola.

## Resumen para explicar

> Los perritos están guardados en la tabla `perritos` de PostgreSQL.
> El backend se conecta con un `Pool` de la librería `pg`, que lee los datos de conexión del archivo `.env`.
> El modelo hace las consultas SQL parametrizadas y usa el alias `idPerrito` para que el JSON salga en camelCase.
> El controlador recibe la petición, llama al modelo y responde con JSON y su código HTTP (200, 201, 204 o 404).
> Las rutas exponen el CRUD en `/api/v1/perritos` con GET, POST, PUT y DELETE.
> En Angular, el servicio usa `HttpClient` para llamar a esa URL y devuelve un Observable.
> El componente del menú se suscribe en `ngOnInit` y muestra los perritos con `console.log`.
